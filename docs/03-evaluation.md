## 运行记录

六条用例由 deepseek-chat 实际运行，`examples/*/input.json` 记录 `provider: llm`。

| 用例 | 输入 | 状态 | 步数 |
|---|---|---|---|
| case01 | 采购 30 万需要谁审批 | 已回答 | 2 |
| case02 | 报销期限多久 | 需澄清 | 7 |
| case03 | 华东区报销单提交时限 | 已回答 | 6 |
| case04 | 期权行权价 | 资料不足 | 4 |
| case05 | 采购 30 万 + 检索故障 | 已回答 | 4 |
| case06 | 年假有几天 → 我工作 12 年了 | 已回答 ×2 | 2 |

case03 中模型未二选一，而是区分为"日常报销按 15 个工作日、差旅按 30 个自然日"作答。
这是模型读完原文后自行区分适用场景，并非规则层 precedence 机制的直接输出；
规则层只看到 front matter 的 `precedence: 1<2`，恰好与模型结论一致（见 05 复盘）。

## 指标

| 指标 | 定义 | 结果 |
|---|---|---|
| 冲突处理正确率 | 按预期动作处理（追问或按优先级作答）的用例数 / 冲突用例数 | 2/2 |
| 缺口识别 | 无覆盖时返回资料不足的用例数 / 超纲用例数 | 1/1 |
| 故障恢复 | 注入故障后仍能作答的用例数 / 故障用例数 | 1/1 |
| 反事实敏感 | 修改文档后答案随之变化的用例数 / 反事实用例数 | 2/2 |

样本规模为 6 条用例，仅作功能验证，不构成统计结论。

## 缺陷记录

| 编号 | 现象 | 原因 | 修复 |
|---|---|---|---|
| D1 | "报销期限多久"直接回答 15 个工作日 | 无冲突检测 | 增加槽位冲突信号与冲突校验 |
| D2 | "密码"检索不到"口令" | 术语表仅对文档侧归一 | 查询与文档双向归一 |
| D3 | "期权行权价"返回 5 条无关片段 | 余弦 0.2 左右仍进入候选 | 增加相关性下限 |
| D4 | 接模型后渲染报错 | 状态缺 `max_steps` | 补齐字段 |
| D5 | 模型反复检索同一内容 | 证据未写入上下文 | 每步生成 evidence 清单 |
| D6 | 模型无法列目录 | 系统提示词缺 `list` 动作 | 补动作定义 |
| D7 | 参数解析为空 | 模型将参数平铺在顶层 | 增加归一化 |
| D8 | 正确答案被拒 | 数量校验把条款号视为数字 | 仅校验带单位的数量 |

## 规模实验

> 以下为离线 benchmark：FAISS 路径（`scripts/build_scale_index.py` + `vector_store.py`）
> 只用于压测，**尚未接入在线 Agent 链路**。在线问答当前只接 12 篇小语料，
> 走 `src/retrieval/` 的内存索引；若把 10 万 chunk 直接灌进在线 Retriever，
> 每次查询是 O(N) 全量打分，不是下表的 0.34ms。FAISS 接入在线链路是下一步。

语料：32 个业务领域的 100,000 个合成 chunk，加 12 篇人工语料，共 100,031 条。

| 指标 | 千问 1024 维 | 本地 bge 512 维 |
|---|---|---|
| 向量化耗时 | 1207s | 543s |
| 消耗 token | 590 万 | — |
| 建索引 | 3.0s | 1.5s |
| 索引大小 | 437MB | 232MB |
| 单次检索 | 0.34ms | 0.16ms |
| 精确扫描 | 6.35ms | 3.88ms |
| 金标进前五 | 5/6 | 3/6 |

未命中项为"退款政策"，合成语料中无退款类文档。12 篇语料下三种后端 top-3 一致，
排序主要由 BM25 与术语表决定。

复现：

```bash
python scripts/gen_scale_corpus.py --docs 10000
python scripts/build_scale_index.py
```

## 限制

- 真实模型输出存在波动，六组记录为一次成功运行。
- 默认语义分支为哈希向量，属字面相似，并非语义向量。
- 冲突信号依赖语料 `slots` 标注，真实场景需模型抽取。
- 显式例外条款（如"不适用 FIN-001 5.2"）规则层无法处理。
- 未实现 reranker、权限过滤与增量索引。
